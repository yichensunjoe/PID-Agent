# Agent 参考图片与视觉模型

P&ID-Agent 的网页 Agent 支持把自然语言和参考图片放在同一次规划请求中，交给具有视觉识别能力的 OpenAI 兼容模型分析，然后继续使用现有语义事务、端口连接、结构化校验和 revision 保护生成可编辑 P&ID。

## 使用方法

1. 打开一张 P&ID，并切换到右侧 **Agent** 面板。
2. 输入自然语言要求，例如：`识别参考图中的设备、仪表和管线连接，按同样流程生成可编辑 P&ID，并把缺少的位号按项目规则补齐。`
3. 在“参考图片”区域选择、拖入或粘贴图片。
4. 检查缩略图和文件名；不需要的图片可以单独移除。
5. 选择支持视觉输入的模型，再执行“自动生成并应用”或“仅生成事务预览”。

图片会同时用于第一次规划和后续结构化重规划。应用成功、切换图纸或手工清除后，网页会释放当前附件。

## 支持范围

- 格式：PNG、JPEG、WebP；
- 数量：最多 4 张；
- 单张解码后大小：最多 8 MiB；
- 合计解码后大小：最多 16 MiB；
- 浏览器到 P&ID-Agent 的视觉规划请求默认上限：24 MiB，可通过 `PID_AGENT_MAX_AGENT_BODY_BYTES` 调整。

普通 JSON 接口仍保持较小的 `PID_AGENT_MAX_JSON_BODY_BYTES` 上限；提高视觉规划上限不会放宽其他写接口。

## 发送格式

后端在验证 data URL、Base64、声明 MIME、文件魔数和体积后，按 OpenAI 兼容 Chat Completions 多模态格式发送：

```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "自然语言、当前文档、场景摘要和 Agent Harness"},
    {
      "type": "image_url",
      "image_url": {
        "url": "data:image/png;base64,...",
        "detail": "high"
      }
    }
  ]
}
```

图片不是绘图元素。模型必须将识别结果转换为真实图例、端口、连接器、连接点和工程属性，不能用截图或装饰线替代可编辑拓扑。

## 数据处理

- 附件仅保存在当前网页内存；
- 不写入 P&ID 文档、SQLite 数据库或项目导出包；
- 诊断日志只记录参考图片数量，不记录图片 Base64；
- 图片会发送给用户选择的外部或本地模型服务，数据处理范围取决于该模型服务的部署与隐私政策；
- API Key 的处理方式不变，图片不进入 Provider 配置。

## 模型兼容性

模型名称出现在 `/models` 中并不代表它支持图片。应选择明确支持视觉输入的模型和兼容接口。若 Provider 对图片或 `image_url` data URL 返回 400、413、415 或 422，P&ID-Agent 会显示“模型或接口拒绝图片输入”的明确错误，而不会静默删除图片后按纯文本继续生成。

纯文本请求保持原有字符串消息格式，因此现有不支持视觉的模型仍可继续处理未附图的自然语言任务。
